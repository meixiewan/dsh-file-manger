# 工作区文件管理

在右侧边栏中管理工作区文件：上传（含批量上传和拖放）、新建文件夹、重命名、移动、复制、删除（二次确认）、搜索、下载和预览。

文件管理器直接绑定**当前会话的工作区根目录**：会话创建时记录的项目目录（`session.header.cwd`），也就是 DSH 对该会话的 `workspace-write` 边界。这个根目录不随会话内的 `cd` 或新建工作树移动：在会话里 `cd` 到子目录、或用 `create_worktree` 切到 `.agents/worktrees/<分支>` 后，文件管理器的根目录仍然是原项目目录（例如 `/workspace/zhsh-mmo-server-main`），工作树作为普通子目录在其中浏览和编辑。只有以工作树自身为项目目录创建的会话，根目录才是该工作树。不创建独立的受管根目录，也不接受任意绝对路径；切换会话后，管理范围随之切换。

## 入口

安装并启用插件、刷新页面后，有两个入口：

1. **右侧边栏 → 更多工具**：点击「工作区文件管理」卡片，打开「工作区文件」标签页。
2. **右侧边栏 → 文件**：在文件树头部工具栏点击「打开工作区文件管理」图标，直接打开管理器。

没有会话或会话没有工作区时，标签页会显示说明，而不是报错。

## 功能

- **浏览**：面包屑导航、上一级、刷新；文件夹优先排序；显示文件大小和修改时间。目录较大时分页加载，每次 500 项。
- **搜索**：在当前目录内按名称筛选；输入后由 Host 扫描当前目录（最多 50,000 项），支持继续加载匹配结果。
- **上传**：工具栏上传按钮或把文件拖入面板；逐个上传并显示进度，可取消；同名文件自动生成 `名称 (1).扩展名`。单个文件最大 8 GiB，单次选择最多 200 个文件、总计 8 GiB，Host 端每个工作区同时处理 2 个上传。
- **新建文件夹**：输入名称即可创建。
- **重命名**：支持仅大小写变化的重命名。
- **移动 / 复制**：在目标目录选择器中确定目标；移动、复制都支持多选。复制遇到同名文件会自动生成唯一名称；移动到同一目录视为无操作。
- **删除**：必须二次确认；确认框列出待删除项并明确提示目录会连同内容递归删除。
- **选择**：单选/全选/按名称筛选；一次最多选择 2000 项，多选后可批量移动、复制、删除。
- **下载**：行内菜单和预览弹窗均可下载原始文件。
- **预览**：文本类文件在弹窗中查看（最多 256 KiB，超出会提示截断）；常见位图图片先向 Host 查询尺寸和像素数，确认安全后才内联加载（最大 32 MiB、4000 万像素）；二进制或超大图片只提供下载。
- **安全**：所有路径都经过规范化并做真实路径（realpath）包含检查，拒绝 `..`、绝对路径、NUL/控制字符、反斜杠和指向工作区外的符号链接。上传和复制先写入目标目录内的隐藏暂存文件或目录，成功后再以排他方式落盘；崩溃遗留的过期暂存项会在后续列举时清理。写操作按工作区串行化，客户端关闭弹窗会尽力中止尚未开始的项目。

## 限制

| 项目 | 上限 |
| --- | --- |
| 单个文件上传 | 8 GiB |
| 单次上传选择 | 200 个文件 / 总计 8 GiB（浏览器端预检） |
| 同一工作区并发上传 | 2 个 |
| 目录分页 | 每次 500 项，可继续加载 |
| 单次目录扫描 | 50,000 项（超出会标记扫描截断） |
| 单次批量操作 / 选择 | 2000 项 |
| 文本预览 | 256 KiB（超出截断） |
| 图片内联预览 | 32 MiB / 4000 万像素（超出只提供下载） |

- 拖放**文件夹**不会递归上传；请逐个选择文件或先打包。
- 符号链接可以重命名、移动或删除（操作链接本身），但不能进入、复制、读取或下载其指向的内容。
- 删除目录会递归删除目录内容，操作不可撤销。
- 移动/复制跨越不同文件系统时由 Host 端回退处理，可能比同盘操作慢。
- 文件管理器只操作当前会话的工作区根目录（会话创建时记录的项目目录）；不能借此访问该目录之外的路径。

## 安装

在本仓库目录中安装开发依赖并执行检查：

```bash
cd /workspace/dsh-file-manager
npm install
npm run check   # 语法检查 + 47 项 node:test（含 12 项真实 React 渲染测试）
```

然后将目录作为 bundle 安装到当前 profile（在 DSH 会话中使用插件管理工具，目标传绝对目录）：

```text
plugin_manager install_bundle target=/workspace/dsh-file-manager
```

安装后刷新 Web 页面。若修改了 Host 代码或页面没有立即出现入口，确认 profile 的 bundle 列表已包含 `@dsh-custom/dsh-file-manager`，并重启对应的 Web 进程。

## 结构

```text
index.js              Host 入口：注册三条精确 Fetch 路由
lib/errors.js         稳定错误码与 wire 错误格式
lib/paths.js          相对路径/名称校验、包含检查、唯一名称
lib/session-root.js   从 sessionId 解析当前会话的工作区根目录（header 项目目录，缺失时回退到工作目录）
lib/mime.js           Content-Type 与 Content-Disposition
lib/image.js          图片头解析与像素预算检查
lib/ops.js            文件操作实现（列举/增删改/移动复制/读写/上传）
lib/routes.js         op、upload、download 路由与请求校验
client.js             Web 客户端：右侧标签页、工具栏、选择器、弹窗、样式
test/                 Host 操作、路由、客户端注册的 node:test 测试
```

### HTTP 路由

全部为 owner-only，非 owner 一律 403。

- `POST /api/dsh-file-manager/op`：JSON 操作请求；要求 `x-dsh-file-manager: 1`。
  请求体 `{ sessionId, action, ... }`，`action` 为 `list`、`mkdir`、`rename`、`move`、`copy`、`delete`、`read`、`image-meta`。
- `POST /api/dsh-file-manager/upload`：流式上传；要求 `x-dsh-file-manager: 1`；
  `Content-Type: application/octet-stream`，查询参数 `sessionId`、`dir`、`name`。
- `GET /api/dsh-file-manager/download`：下载/预览；查询参数 `sessionId`、`path`、`inline`。

响应遵循 Harness 约定：成功 `{ ok: true, value }`，领域错误 `{ ok: false, error: { code, message, details? } }`。

## 开发

```bash
npm run check   # 全部 JS 语法检查 + 47 项 node:test
```

客户端注册测试在 Node `vm` 中加载 `client.js`，验证标签类型、引导卡片、三个 slot 注册、双语字典键一致性和样式生命周期。Host 测试覆盖路径逃逸、大小写重命名、分页/搜索、暂存文件与目录清理、符号链接复制逃逸、取消批次、上传限额和图片预检。另有 12 项真实 React 渲染测试，覆盖列表/筛选/选择、新建文件夹、重命名、复制、移动、删除确认、上传、分页、搜索、错误状态和不安全图片拒绝；未安装开发依赖时这组测试会自动跳过。渲染测试仍不替代浏览器中的真实视觉和鼠标交互验证。
